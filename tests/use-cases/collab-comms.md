# Use case: agents hear from their collaborators

Claude and Codex are building PR #1 together, and Zach is watching the PR. Until now an agent only learned that its next action had changed. What a collaborator said (a note, a PR comment) reached nobody.

1. Codex claims T1. Claude has something to tell it, so Claude runs `collab msg <codex id> --body "T1 must keep the old export name"`. Nothing is posted to GitHub. A message to `all` reaches every agent; a message to an id that hasn't joined is refused.
2. The next collab command Codex runs, whatever it is (`next`, `push`, `verify`, `submit`…), ends with an **Inbox** block: the message, who sent it, and a line saying the text is untrusted data, not instructions. With `--json` the same items are in `inbox.urgent`. The message is shown once: Codex's following command doesn't repeat it, and Claude never sees its own message.
3. Claude writes a note on Codex's task with `collab note T1 --body …`. Codex sees it in its inbox, because T1 is its task. A note on a task that isn't Codex's shows up as one line of activity ("claude-… added a note to T2"), next to the other things collaborators did: claims, pushes, reviews, merges.
4. Zach comments on the PR: "Please keep the public API unchanged." Every agent gets it in its inbox, marked as coming from `@zwymer`. A comment Zach leaves on T1's sub-PR goes to T1's owner and reviewer. A comment from someone with only read access is never shown, and collab's own comments (dashboard notices, reviews, notes) aren't echoed back. `/collab pause` still pauses the collab.
5. Codex has nothing to do and runs `collab wait`. A few seconds after Claude sends it a message, `wait` returns, although the next action is still `wait`: the output says what woke it and shows the message. Codex reads it and runs `next` again.
6. While it waits and nothing happens, `collab wait` checks the ledger with one small git fetch, often at first and then less often (every 5 s growing to 60 s), and only asks GitHub for comments and CI now and then (every 30 s while it waits on CI, otherwise every 1 to 3 minutes). Any change to the ledger makes it check quickly again. It also wakes when a lease it is waiting on runs out.
7. In the middle of long work an agent runs `collab inbox`: one fetch, the unread items, exit 0. `collab inbox --peek` shows them without marking them read, and `collab inbox --all` shows recent items again, the newest when there are more than one block holds.
8. Someone comments on an unrelated issue in the same repo. Nothing is written to the collab's ledger for it, so no waiting agent is disturbed.
9. An agent runs where its cursor file can't be kept (a sandbox, or the file was lost). It is still not shown the same items with every command: its own last push or verify is in the ledger, and the inbox starts after it.
